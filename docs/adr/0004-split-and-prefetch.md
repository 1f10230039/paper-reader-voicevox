# 0004. 文は 90 文字で分割し、2 文先読みする

- Status: Accepted

## Context

読み上げは文単位で進める（ハイライトとシークの単位でもある）。
論文の文は長く、1 文が 200 文字を超えることも珍しくない。
Web Speech API は長い発話が途中で止まる癖があり、VOICEVOX は合成に文の長さに比例した時間がかかる。

## Decision Drivers

- 文と文の間が空かないこと
- シーク（前の文・次の文）の粒度が実用的であること
- ブラウザ内蔵音声の「長文で止まる」癖を避けること

## Considered Options

1. **句点で分け、90 文字を超える文は読点でさらに分ける。次の 2 文を先読みする**
2. 句点だけで分ける — 長い文がそのまま残り、合成待ちと途中停止が起きる
3. 段落ごとにまとめて合成する — 待ち時間が長く、シークが粗い

## Decision

オプション 1 を採用する。分割の上限は 90 文字。再生中に次の 2 文を先に合成しておき、
合成結果は `話者|速度|文` を鍵に Promise ごとキャッシュする。先読みと本再生が同じ Promise を
共有するので、二重に合成しない。

## Consequences

- (+) 文の間が空かず、途中で止まらない
- (+) 1 発話が短いので、シークの粒度が細かい
- (−) 読点の位置によっては、意味の途中で区切られることがある
- (−) 速度や話者を変えるとキャッシュの鍵が変わり、先読みし直しになる
